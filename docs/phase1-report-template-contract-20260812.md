# 00401 一期客户报告模板契约

**确认日期**：2026-08-12
**权威模板**：`docs/260807胜任力开发资料/胜任力测评报告样例.docx`
**模板SHA-256**：`71648879883952f2199df0ec1f973bcd462d7bb9674f0960b4a6c11da7c4d053`

## 1. 模板定位

客户提供的DOCX不是单纯的视觉参考，而是一期报告的完整样例契约，包含：

1. 固定格式；
2. 固定文本；
3. 按测评对象和作答结果变化的文本；
4. 人员、时间、分数和等级等变量；
5. 图表及变量在图表中的位置和表达方式；
6. 固定十页的内容顺序和分页关系。

程序中的Vue/Chromium PDF模板应复现该契约。客户以后修改DOCX时，代表模板结构、固定文字或呈现规则可能发生变化；程序不会直接执行DOCX，因此仍需将变更同步到Vue/PDF模板并重新验收。

## 2. 固定格式

以下内容随`competency-phase1-report-v1`模板版本冻结：

- A4页面及10个物理页；
- 绿色主视觉、封面层级、页眉页脚和页码；
- 页面顺序：封面、阅读说明、个人/总体/效度、一级维度、二级维度总览、5页二级维度详情；
- 标题层级、信息区块、得分区、等级区、诊断区和图表位置；
- 两个一级维度独立以1至5分表达；
- 十个二级维度使用10轴雷达图；
- 二级维度详情按客户DOCX连续排版并跨页衔接：定义、得分/等级、诊断依次呈现，必要时同一维度的定义与结果跨物理页；
- 字号、颜色、边框、留白及不裁切、不重叠、无空白物理页规则。

## 3. 固定文本

以下文字由客户DOCX提供，属于模板或静态报告内容，不应在Vue中临时改写：

- 报告名称“胜任力测评报告”；
- 英文名称“Competency Assessment Report”；
- 标语“洞悉深层素质 ● 驱动精准发展”；
- “报告阅读说明”“报告详细解读”“个人信息”“总体评价”等固定标题；
- 阅读说明中的理论背景、两个一级维度及十个二级维度介绍、应用场景；
- “特别说明”全文；
- 一级维度等级说明；
- 二级维度图示说明；
- “通用能力”和“心理素养”两条维度说明；
- “得分”“评价等级”“诊断”等固定字段标签。

其中业务静态文字应进入CSV或经批准的内容版本；纯结构标签随Vue模板版本维护。不得因为文本在DOCX中固定，就绕过内容审核和版本冻结。

## 4. 可变字段

以下值来自测评、人员、试卷和结果快照：

| 区域 | 可变字段 | 数据来源 |
|---|---|---|
| 封面 | 报告日期 | 报告生成时间 |
| 个人信息 | 姓名、年龄、性别、手机号、单位、岗位 | 结果中的人员快照，按`requiredFields`显示 |
| 时间 | 完成时间、答题时长 | 试卷/结果快照 |
| 总体评价 | 总体得分、总体等级 | 十个二级维度的正式计分结果 |
| 效度 | 效度状态对应提示 | 效度结果 + 内容版本；受测者不显示原始分和阈值 |
| 一级维度 | 通用能力、心理素养得分及等级 | 两组一级结果 |
| 二级维度 | 十维得分、等级及雷达图坐标 | 十条二级维度结果 |
| 页脚 | 内容版本、报告模板版本 | 报告实例快照 |

DOCX中的示例日期、示例分数、示例等级和示例人员信息只表示变量的版式位置，不得作为正式报告固定值。

## 5. 条件变化文本

以下文字必须按稳定匹配键从批准内容版本读取：

- 总体诊断：`总体等级编号 + 内容版本 + 报告对象`；
- 二级维度诊断与建议：`维度ID + L1-L5 + 内容版本`；
- 效度提示：`good/questionable + 内容版本`；
- 最终免责声明：批准内容包；
- 一级维度说明：`group code + 内容版本`。

一期目前固定为基层员工对象，但匹配键仍需保留报告对象，禁止跨对象、跨内容版本或缺失时回退。

## 6. 当前程序对照

当前已实现：

- 固定十页A4；
- 绿色结构；
- 个人、时间、总体、一级和二级结果变量；
- 10轴雷达图；
- 5页双维详情；
- CSV驱动维度名称、定义和等级标签；
- 后端内容快照驱动总体、维度和效度诊断；
- 双批准与内容完整性门禁。

当前已完成的视觉对齐：

- 复用客户DOCX内嵌封面插画；
- 对齐封面标题、英文名、标语、日期和渐变圆形装饰；
- 阅读说明使用客户式连续正文和双色十维矩阵表；
- 总体评价使用五档环绕图；
- 一级维度使用得分表、双色饼图和结果分析框；
- 二级维度使用居中10轴雷达图、外围标签和图示说明；
- 详情页改为客户式连续定义框、环形得分、等级和诊断，并按原稿跨页衔接；
- 真实staging PDF与客户PDF按相同DPI逐页并排检查，保持A4十页。

仍需客户测试确认：

- 将DOCX完整阅读说明和特别说明拆入可审核的静态文本数据；
- 固定标题、字段标签、等级说明和图示说明逐项对照DOCX；
- 当前页面级视觉基线是否达到客户接受程度；
- 客户修改DOCX后执行差异提取并同步Vue；
- 客户修改CSV后重新校验、生成运行目录并同步正式内容数据；
- 内容和模板均定稿后重新执行真实数据、Chromium DOM及10页A4 PDF验收。

## 7. 客户维护边界

- 客户修改业务文字、维度定义、等级诊断和效度提示：修改CSV；
- 客户修改固定格式、固定标题、固定说明、页面顺序或视觉：修改DOCX；
- 同一段文字若同时存在于DOCX和CSV，以后应指定唯一维护源，避免双份内容漂移；
- 客户提交修改后需同时提供文件版本和SHA-256；
- 程序同步、校验、staging验收和production上线仍分别执行，不能把替换文件等同于完成部署。
