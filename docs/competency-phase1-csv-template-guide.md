# 00401 一期 CSV 数据模板说明

## 1. 用途

本目录对应的数据包位于 `scripts/data/competency-phase1-csv/`，用于：

1. 人工检查和修订一期90道题；
2. 人工检查10个二级维度定义；
3. 人工检查50条二级维度L1–L5诊断与建议；
4. 人工检查5条总体诊断；
5. 补充一级维度、效度提示、免责声明和双批准资料；
6. 后续经预览、备份和事务校验后导入数据库。

CSV均使用 UTF-8 BOM、CRLF 和标准双引号转义，可直接用Windows Excel打开。

## 2. 文件清单

| 文件 | 数据行 | 用途 |
|---|---:|---|
| phase1-package.csv | 1 | 四类版本、来源SHA、报告对象、双批准、环境和最终免责声明 |
| phase1-questions.csv | 90 | 80道维度题和10道效度题 |
| phase1-dimensions.csv | 10 | 二级维度身份、核心含义和完整定义 |
| phase1-dimension-levels.csv | 50 | 10维度×L1–L5诊断与建议及精确边界 |
| phase1-overall-levels.csv | 5 | 总体五档诊断及精确边界 |
| phase1-report-static-texts.csv | 4 | 2条一级说明及效度good/questionable提示 |

## 3. 人工可修改字段

- phase1-questions.csv：`题目内容`、`考察点`、`审核状态`、`审核备注`；计分方向确需修正时必须记录原因。
- phase1-dimensions.csv：`核心含义`、`定义`、`审核状态`、`审核备注`。
- phase1-dimension-levels.csv：`诊断与建议`、`审核状态`、`审核备注`。
- phase1-overall-levels.csv：`诊断`、`审核状态`、`审核备注`。
- phase1-report-static-texts.csv：`内容`、`审核状态`、`审核备注`。
- phase1-package.csv：批准资料、生效环境、最终免责声明和定稿后的`正式内容源SHA256`。

审核状态统一使用：

- `pending_review`：待审核；
- `approved`：已审核确认；
- `rejected`：拒绝采用；
- `missing_required`：必需内容尚未提供。

## 4. 禁止直接修改的稳定字段

除非另行执行身份迁移，不得修改：

- 契约版本、四类产品版本、报告对象；
- 顺序、来源行；
- 题目编号、题目类型；
- 一级维度编号和名称；
- 维度ID、编号和名称；
- 维度内题号；
- 等级编号、总体等级编号；
- 精确边界字段；
- 原始题本文件及SHA、报告模板文件及SHA。

`显示区间`只用于报告展示；系统计分必须使用`最小分/包含最小分/最大分/包含最大分`。

边界包含标志固定使用数字：`1`表示包含该边界，`0`表示不包含，最高档无上界时最大分和包含最大分均留空。不得改为TRUE/FALSE、是/否或数学符号。

## 5. 当前明确缺失项

- `phase1-report-static-texts.csv`中的效度良好提示已有AI建议稿，状态为`pending_review`；客户及心理测量负责人可直接修改该行，确认后再改为`approved`；
- `phase1-package.csv`批准状态为`draft`；
- 内容批准人与时间为空；
- 测量批准人与时间为空；
- 生效环境为空；
- 最终免责声明已有客户DOCX“特别说明”候选文本，但仍随draft包等待客户及心理测量负责人确认；
- 正式内容源SHA为空。

效度良好建议稿的来源明确标记为“AI建议稿-待客户确认”，不代表正式批准。其余空白批准资料、环境、最终免责声明和SHA不得由程序自动编造。

## 6. 校验流程

人工审阅期间运行：

`node scripts/tools/validate-competency-phase1-csv.js scripts/data/competency-phase1-csv`

该模式检查编码、文件集、表头、稳定身份、行数、唯一性、题型、方向和精确边界，允许审核状态未完成。

校验器还会拒绝以`=`、`+`、`-`、`@`开头的单元格，防止人工CSV在Excel或后续导入阶段触发公式注入。确有文案需要以这些字符开头时，应改写为普通文字表达。

全部内容定稿后：

1. 先运行审阅模式，取得输出的`content_source_sha256`；
2. 将该值填入phase1-package.csv的`正式内容源SHA256`；
3. 将所有待导入行的审核状态改为`approved`；
4. 补齐双批准、环境和最终免责声明；
5. 运行批准导入模式：

`node scripts/tools/validate-competency-phase1-csv.js scripts/data/competency-phase1-csv --require-approved`

批准导入模式通过前，禁止写数据库或开放正式报告入口。

`content_source_sha256`按文件名排序，对除phase1-package.csv外的5个CSV执行“文件名 + 换行 + 原始文件字节 + 换行”的连续SHA-256计算。这样填写SHA不会产生自引用循环；任何内容、审核状态或换行变化都会使旧SHA失效。

## 7. 保存注意事项

1. Excel保存时选择“CSV UTF-8（逗号分隔）”；
2. 每个CSV只保留一个工作表；
3. 不增加、删除或重命名列；
4. 不插入标题行、说明行、空白行或合计行；
5. 不把题号、维度编号转换为日期或科学计数法；
6. 文案内可以换行，必须由Excel按标准CSV引号保存；
7. 修改后先关闭Excel，再运行校验器，避免文件锁或未落盘内容。

## 8. 后续数据库替换纪律

CSV校验通过不等于允许直接上线。后续导入必须依次执行：

1. 只读预览和变更差异报告；
2. staging数据库完整备份；
3. 题目及正式报告文案单事务替换；
4. SQL行数、唯一键和内容SHA复核；
5. 90题完整作答、计分、效度和十页PDF验收；
6. 清理测试数据并报告结果；
7. production仍需单独上线授权。

## 9. 报告模板目录再生成

CSV中的维度名称、定义和等级标签会生成前端运行目录。人工修改CSV并通过校验后，必须执行报告目录生成器；生成文件位于Go项目前端源码目录，只存放可编译运行数据，不在其中手工维护文案。

生成后运行同一工具的`--check`模式。若CSV已变化但目录未重新生成，检查必须失败，禁止构建或部署旧报告模板。

## 10. 客户后续修改入口

1. 业务名称、维度定义、等级标签、诊断建议和效度提示统一修改6个CSV中的对应行；
2. 报告固定格式、固定文本、分页、版式和内容顺序修改客户报告模板DOCX，并提供修改后的文件SHA-256；
3. DOCX是完整报告样例契约，不只是视觉参考；它包含固定格式、固定文本、变量位置、条件文本位置和示例分数。程序不会直接执行DOCX，模板文件变化后仍需对照修改Vue/PDF模板并重新执行10页A4验收；
4. CSV变化后必须重新校验并生成前端运行目录；
5. 客户确认全部内容后，再补齐双批准、正式内容源SHA、生效环境和最终免责声明，不得提前把建议稿标记为正式内容。

固定/可变字段的完整分类见`docs/phase1-report-template-contract-20260812.md`。
