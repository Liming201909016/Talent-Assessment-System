# 00401 胜任力正式题目导入操作指南

> 适用环境：生产 `http://39.106.61.48:8090/`（无端口80入口放通后改用正式无端口地址）
>
> 00401是系统动态生成的胜任力题库入口，不是传统`el_repo`物理题库。生产已初始化48个维度，初始题目数为0。

## 一、导入前门禁

1. 由运维完成生产数据库备份并记录SHA-256。
2. 确认导入账号具备胜任力题目管理权限。
3. 先进入“题库管理 → 00401 胜任力测验题库 → 维度维护”，确认：
   - 维度总数为48。
   - 编号D01～D48连续。
   - 名称、顺序、VIRD、适用类别和核心含义已经业务确认。
   - 准备导题的维度处于启用状态。
4. 不使用staging的384道AI测试题作为正式题库。

## 二、模板字段

在00401页面点击“下载模板”。模板固定九列：

1. 维度序号
2. 维度名称
3. 题目编号
4. 维度内题号
5. 题目内容
6. 考察点
7. 计分方向
8. 启用状态
9. 备注

### 填写规则

- 维度序号：1～48。
- 维度名称：必须与后台当前维度名称完全一致。
- 题目编号：全局唯一，建议采用`D01-Q01`格式。
- 维度内题号：同一维度内唯一且为正整数。
- 题目内容、考察点：不能为空。
- 计分方向：仅允许“正向/反向”（导入后对应`forward/reverse`）。
- 启用状态：仅允许模板约定的“启用/停用”。
- 备注：应填写题目来源、版本或审核状态；正式题目不要保留“AI测试题-未信效度验证”标记。
- 不修改表头，不新增合并单元格，不改变工作表结构。
- 系统模板内的示例题必须修改或删除，不能原样导入正式库。

## 三、分批导入策略

1. 首批建议每个维度导入1～2题，用于验证格式和计分方向。
2. 首批验证通过后，再按业务确认的批次导入剩余正式题目。
3. 单个文件内出现任意错误时，不执行正式导入；先修正全部错误。
4. 每个正式批次导入前建立独立数据库备份点。
5. 保存每批原始XLSX、预览SHA-256、成功数、错误数、操作人和操作时间。

## 四、操作步骤

1. 登录管理后台。
2. 进入“题库管理”。
3. 打开“00401 胜任力测验题库”。
4. 点击“导入题目”，选择填写完成的XLSX。
5. 点击预览：
   - 预览阶段不写数据库。
   - 核对成功行数、错误行数、逐行错误信息和SHA-256。
6. 只有错误数为0且成功数符合预期时，点击确认导入。
7. 系统会重新校验同一文件及SHA-256，成功后才在单个事务中批量写入。
8. 导入后刷新列表，按维度、状态和题号筛选核对。
9. 点击“导出题目”，下载当前00401全量题目并与原始文件对比。

## 五、导入后验收

### 数据验收

- 题目总数与客户交付清单一致。
- 每个维度题数符合业务设计。
- 题目编号全部唯一。
- 每维度内部题号无重复。
- 正向/反向数量和分布符合业务设计。
- 启用/停用状态正确。
- 题干、考察点、备注无乱码、截断或模板示例残留。

### 页面抽查

每个批次至少抽查：

- 一道正向题。
- 一道反向题。
- 一道停用题（如有）。
- 维度首题和末题。
- 中文标点、长文本和特殊字符题目。

### 创建测评门禁

在题目验收签字前，不创建或发布正式胜任力测评。题目验收完成后：

1. 新建胜任力测评草稿。
2. 选择报告对象版本。
3. 只选择已有启用题目的维度。
4. 核对系统显示的各维度题数和总题数。
5. 发布并冻结题目快照。
6. 使用专门测试人员完成一次全链验收后，再开放正式参与者。

## 六、临时报告说明

当前生产报告内容版本为`temp-v1`，报告页面和PDF带有“临时测试报告/不可作为人才决策依据”警示。在客户正式报告文案交付并以新content version发布前：

- `temp-v1`仅用于流程和布局验证。
- 不得作为招聘、晋升、淘汰或任用依据。
- 不得去除临时警示后对外作为正式报告。

## 七、异常处理

- 预览失败：不写数据库，修正文件后重新预览。
- 正式导入失败：事务整体回滚；保留错误信息和文件，不重复盲点确认。
- 导入数量异常：立即停止后续批次，核对导出文件和数据库备份点。
- 发现错误题：优先在00401专用页面编辑或停用；已经发布的测评继续使用发布快照，不受源题后续编辑影响。
- 需要批量回滚：必须依据该批次明确题目主键和备份点制定脚本，不执行全表删除。
