# 业务链定义

> 本文件是跨页面、API、数据库验收链的索引。具体条件分支见 [business-branches.md](business-branches.md)。

## Chain-L01：传统测评（001/002/003）

1. 管理员创建传统测评并关联题库。
2. 创建试卷，按题库规则冻结 `el_paper_qu` 与答案。
3. 读取试卷和单题详情。
4. 保存答案并交卷。
5. 查看结果、标准分、导出或报告。
6. 删除测试数据时按 paper → exam 顺序清理。

**不变量**：传统接口只处理 `assessment_type=legacy + scoring_mode=legacy`，不得读写胜任力源题或快照。

## Chain-C01：胜任力主数据与题库

1. 管理员维护第一期10个稳定维度（`A1-01`～`A1-05`、`B1-01`～`B1-05`）及启停状态。
2. 通过00401专用页筛选、编辑、启停源题。
3. 使用十列题型感知模板执行下载 → 选择 → 预览 → SHA-256确认 → 正式导入。
4. 题目身份字段保持不可变；源题修改只影响未来发布。

**不变量**：00401为虚拟入口，不写 `el_repo/el_qu_repo`；传统题目接口不得操作 `dimension_id IS NOT NULL` 或 `competency_question_type IS NOT NULL` 记录。当前staging题本固定为80道 `dimension` 和10道 `validity`，效度关联维度只作来源追踪。

## Chain-C02：胜任力配置与发布

1. 创建 `competency + competency_average` 草稿。
2. 后端固定报告对象为基层员工、固定十个A/B维度及其顺序，并固定四类一期版本；客户端不能替换。
3. 验证十维均启用，且每维恰有8道启用维度题和1道启用效度题。
4. 保存草稿并只读展示基层员工/十维/90题和四类版本信息。
5. 在一期五档、一级聚合和效度运行时全部实现前，前后端共同禁止发布，避免旧算法冒充一期版本。
6. 后续解除门禁时，发布必须重新读取维度主数据与90道启用源题，在同一事务冻结四类版本、一级/二级维度、题型和题目快照。

**不变量**：已发布测评的四类版本、维度集合和报告对象不可修改；运行时只读发布快照。

## Chain-C03：参与者答题

1. candidate/tester获得绑定participant/exam的短时令牌。
2. 首次进入锁定参与者并创建一份试卷。
3. 对全部发布题执行安全Fisher–Yates并固化题序。
4. 刷新、重登或断点续答返回相同试卷和题序。
5. 每次保存校验paper token、题目归属、状态、时限和1–5原始值。
6. 手工提交要求全部作答；到期由服务端或Worker可信判定。

**不变量**：参与者响应不返回方向、最终分、维度分或整体分。

## Chain-C04：计分、结果与报告数据

1. 提交事务锁定试卷。
2. 一期按冻结题型拆分80道维度题和10道效度题；效度题不进入二级、一级或总体分。
3. 二级维度每维8题精确平均并分L1-L5；两个一级维度各聚合固定5维；总体为十维分之和并分五档。
4. 效度按10道原始分累加，35及以下良好、36及以上存疑；未完成不产生正式效度分。
5. 原子写10条二级、2条一级、1条效度和1条总体结果；不完整总体分保存NULL。
6. 更新paper及参与者完成时间。
7. 管理端查看、排序和逐题审计。
8. 管理端可筛选效度状态；分数排名默认只纳入完整且效度良好答卷。
9. 一期正式报告使用批准内容版本提供诊断和结果数据；可由客户维护的Word模板填充49个动态字段并更新12个原生图表，默认参考MBTI模式由服务器LibreOffice转换PDF，Microsoft Graph保留为可选转换器。Word转换不可用时可配置回退Vue/Chromium；后端仍仅在内容包双批准且总体/一级/二级/效度/免责声明文案完整时生成。

**不变量**：重复或并发提交只产生一套结果；报告数据不重新计分。

**一期运行时**：发布冻结2组、10维和90题；提交持久化10+2+1+1结果。正式报告模板已本地通过10页A4验证，但当前CSV包仍为draft且缺效度良好提示/最终免责声明，正常生成下载继续由批准门禁关闭。

## Chain-C05：动态导出

1. 从测评管理或结果管理触发导出。
2. 按显式测评类型分流，传统测评保持原实现。
3. 胜任力读取已保存整体/维度结果、个人答题和发布快照。
4. 输出 `结果汇总 / 逐题明细 / 题目字典` 三个Sheet。
5. 动态维度列按冻结顺序，两个既有导出入口返回同一口径。

## Chain-C06：到期Worker

1. 服务启动立即扫描，随后按配置周期扫描。
2. 单次查询按 `limit_time,id` 分批加载过期试卷并解析人员类型。
3. 每份调用与前端相同的幂等提交服务。
4. 单份失败记录paper ID并继续；下轮重试。
5. shutdown取消context并停止ticker。

## Chain-C07：整链删除

1. 管理员确认删除胜任力测评。
2. 单事务按报告 → 一级/效度/二级/整体结果 → 答案/试卷题 → 人员 → 试卷 → 题目快照 → 二级维度快照 → 一级分组快照 → 配置 → 测评顺序物理删除。
3. 任一步失败整体回滚。
4. 删除后验证所有业务表零残留、零孤儿。

## Chain-C08：临时测试报告/PDF

1. 只允许完整答卷进入报告数据。
2. 按结果冻结的内容版本、受众、总体等级、维度与等级精确匹配文案；当前兼容默认值为 `temp-v1`。
3. 按冻结的内容和模板版本保存文案与成绩快照并创建唯一报告实例。
4. Chromium渲染带显著临时警示的PDF，保存路径、大小和SHA-256。
5. 下载校验允许目录并记录审计；重生成复用实例并记录动作。
6. 测评整链删除先清理审计/实例，再清理结果和试卷，最后删除PDF文件。

**限制**：temp-v1只用于系统功能验证，不可作为人才决策依据。客户正式文案、正式题库与生产content version仍延期。

## Chain-C09：一期A/B维度身份重置（staging）

1. 重置前完整备份数据库和已有胜任力报告文件，并记录传统001/002/003基线摘要。
2. 停止应用写流量并保持维护窗口，避免整链删除、预检与身份替换之间产生新测评或报告。
3. 对每个胜任力测评调用既有整链删除，由应用事务清业务行并在提交后删除其允许目录内PDF；逐个验证原报告路径不存在。
4. 验证胜任力测评、运行快照、试卷题、结果和报告依赖均为零；任一残留都阻断009迁移。
5. 在同一数据库会话显式设置staging环境和写流量已停止授权变量，再执行009；脚本获取会话级迁移锁后，在事务内写入一次性marker并清胜任力源题关系/答案、源题、旧临时报告文案和退役维度主数据。
6. 009初始化且仅初始化一期十个A/B稳定身份；不推断尚未确认的第二、三期总体维度池。
7. 第二次执行009时marker使所有破坏性语句和种子替换成为no-op。
8. 重置后验证十维身份、零退役身份、零旧源题/文案，并确认传统001/002/003基线摘要不变，再恢复写流量。

**不变量**：本链只授权staging；production不执行。009不直接删除测评、试卷、人员、结果或报告实例，也不导入90题或创建新的评分/报告文案。
