# 业务链定义

> 本文件是跨页面、API、数据库验收链的索引。具体条件分支见 [business-branches.md](business-branches.md)。

## Chain-L01：传统测评（001/002/003）

1. 管理员创建传统测评并关联题库。
2. 创建试卷，按题库规则冻结 `el_paper_qu` 与答案。
3. 读取试卷和单题详情。
4. 保存答案并交卷。
5. 查看结果、标准分、导出或报告。
6. 删除测试数据时按 paper → exam 顺序清理。

**不变量**：传统接口只处理 `assessment_type=legacy + scoring_mode=legacy`，不得读写胜任力源题或快照。

## Chain-C01：胜任力主数据与题库

1. 管理员维护48个维度及启停状态。
2. 通过00401专用页筛选、编辑、启停源题。
3. 使用九列模板执行下载 → 选择 → 预览 → SHA-256确认 → 正式导入。
4. 题目身份字段保持不可变；源题修改只影响未来发布。

**不变量**：00401为虚拟入口，不写 `el_repo/el_qu_repo`；传统题目接口不得操作 `dimension_id IS NOT NULL` 记录。

## Chain-C02：胜任力配置与发布

1. 创建 `competency + competency_average` 草稿。
2. 选择且仅选择一种报告对象版本。
3. 选择至少一个启用且有启用题目的维度。
4. 保存草稿并显示题数。
5. 发布时重新读取维度主数据与启用源题。
6. 同一事务冻结维度和题目快照并记录发布时间。

**不变量**：已发布测评的维度集合和报告对象不可修改；运行时只读发布快照。

## Chain-C03：参与者答题

1. candidate/tester获得绑定participant/exam的短时令牌。
2. 首次进入锁定参与者并创建一份试卷。
3. 对全部发布题执行安全Fisher–Yates并固化题序。
4. 刷新、重登或断点续答返回相同试卷和题序。
5. 每次保存校验paper token、题目归属、状态、时限和1–5原始值。
6. 手工提交要求全部作答；到期由服务端或Worker可信判定。

**不变量**：参与者响应不返回方向、最终分、维度分或整体分。

## Chain-C04：计分、结果与报告数据

1. 提交事务锁定试卷。
2. 正向按raw、反向按 `6-raw` 计算题目最终分。
3. 维度按已答题平均；零答维度无有效得分。
4. 整体分为有效维度平均分之和，总体评价为整体分除以有效维度数。
5. 写一条整体结果和N条维度结果，更新paper及参与者完成时间。
6. 管理端查看、排序和逐题审计。
7. 完整答卷可进入报告数据；不完整答卷仅保留管理审计。

**不变量**：重复或并发提交只产生一套结果；报告数据不重新计分。

## Chain-C05：动态导出

1. 从测评管理或结果管理触发导出。
2. 按显式测评类型分流，传统测评保持原实现。
3. 胜任力读取已保存整体/维度结果、个人答题和发布快照。
4. 输出 `结果汇总 / 逐题明细 / 题目字典` 三个Sheet。
5. 动态维度列按冻结顺序，两个既有导出入口返回同一口径。

## Chain-C06：到期Worker

1. 服务启动立即扫描，随后按配置周期扫描。
2. 单次查询按 `limit_time,id` 分批加载过期试卷并解析人员类型。
3. 每份调用与前端相同的幂等提交服务。
4. 单份失败记录paper ID并继续；下轮重试。
5. shutdown取消context并停止ticker。

## Chain-C07：整链删除

1. 管理员确认删除胜任力测评。
2. 单事务按结果 → 答案/试卷题 → 人员 → 试卷 → 发布快照 → 配置 → 测评顺序物理删除。
3. 任一步失败整体回滚。
4. 删除后验证所有业务表零残留、零孤儿。

## Chain-C08：临时测试报告/PDF

1. 只允许完整答卷进入报告数据。
2. 按冻结受众、总体等级、维度与等级精确匹配 `temp-v1` 文案。
3. 冻结文案与成绩快照并创建唯一报告实例。
4. Chromium渲染带显著临时警示的PDF，保存路径、大小和SHA-256。
5. 下载校验允许目录并记录审计；重生成复用实例并记录动作。
6. 测评整链删除先清理审计/实例，再清理结果和试卷，最后删除PDF文件。

**限制**：temp-v1只用于系统功能验证，不可作为人才决策依据。客户正式文案、正式题库与生产content version仍延期。
